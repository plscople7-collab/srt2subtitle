# v0.2 ADR

## ADR-001: SRTを中間形式に採用する

状態: accepted  
決定: ローカル音声認識アプリとWeb変換サービスの境界はSRTにする。  
理由: 音声認識エンジン依存をWeb仕様へ持ち込まないため。  
影響: Whisper系、API系、他アプリ由来SRTを共通扱いできる。  

## ADR-002: 音声認識をローカル分離する

状態: accepted  
決定: Whisper等の重い音声認識は各PCで実行し、Web側では扱わない。  
理由: Cloudflare上の負荷、運用、配布、速度、認証の複雑性を避けるため。  
影響: Web側は軽量な共有変換器として成立する。  

## ADR-003: Cloudflare Pages + Workers + D1 + R2 を採用する

状態: accepted  
決定: UI配信はPages、APIはWorkers、メタデータはD1、原本保存はR2に分ける。  
理由: 共有と軽量変換を両立しやすいため。  
影響: サーバーレス前提で再設計する必要がある。  

## ADR-004: プリセット共有を正式機能にする

状態: accepted  
決定: 見本EXO、字幕ルール、既定レイヤーを束ねた話者プリセットを共有対象にする。  
理由: 同じ見た目やルールを案件横断で再利用するため。  
影響: プロジェクト用設定と共有プリセットのデータモデル分離が必要。  

## ADR-005: Web共有範囲は身内限定にする

状態: accepted  
決定: 初期の共有運用は身内限定とし、認証必須にする。  
理由: 完全公開前提にすると認可や悪用対策が重くなるため。  
影響: 初期版は共同編集前提だが、厳密な権限制御は後回しにする。
